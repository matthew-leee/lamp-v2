### 1-Click Excel/CSV Bulk Sync & Admin Concurrency Guards (2026-10-24)
- **Bulk sync backend (`DATA-01`, `ADMIN-01`)**: new `api/src/csv_sync.rs` with `GET /api/admin/csv/{products,site-content}` exports plus `/preview` and `/commit` (all behind `require_admin` + CSRF). Exports start with a UTF-8 BOM (Excel Traditional Chinese), use CRLF and `#01;#02` piece notation (Excel would turn `01-02` into a date). Preview and commit run the same pure planning pass (per-row diffs, validation errors, stock warnings); commit writes products, content, pieces and one `csv_bulk_sync` audit row in a single transaction, and scientific-notation cells are rejected.
- **Conflict-safe stock handling (`DATA-01`, `STOCK-01`)**: exports carry `snapshot_stock_total` alongside `stock_total`/`stock_delta`. An unedited stock column can never clobber the locked live count; edited stock compares the snapshot with the locked DB count and resolves via `stock_conflict_mode` (`apply_delta` default — a mid-edit sale is never rewound — `keep_db`, or `force_override`), while `stock_total >= stock_reserved + stock_quarantined` is always enforced. Slug renames require explicit `allow_slug_rename`.
- **Operator UI (`DATA-01`)**: new `web/components/admin-csv-sync-client.tsx` mounted on `/admin/products` and `/admin/site-content` (export → edit in Excel → dry-run diff → one-click commit) plus the `/admin/api/csv/[...slug]` proxy that attaches the admin session cookie, enforces same-origin CSRF, forces `X-Requested-With`, caps uploads at 8 MB and revalidates only on `/commit`. Any input or option change invalidates the preview, so an unpreviewed file cannot be committed.
- **Admin Studio concurrency & stale-tab guards (`ADMIN-01`)**: product saves send `expected_version_hash` (a tab holding an older row gets `409` instead of silently overwriting a newer save); the URL slug is read-only behind `⛓ Unlock URL Slug` (renames cascade onto historical order lines only as a deliberate act); `sessionStorage` drafts persist their base version across session expiry; and checkout/order pages render deactivated SKUs from the order's stored line-item snapshot (`model`, brand, photos, art config, dimensions) instead of failing on a missing catalogue row.
