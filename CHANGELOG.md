### Reviewer (`gpt-6.1-sol`) round-2 findings fixes — Bounded Task 4
- **Recoverable claim state separated from confirmed delivery (`G02`)**: `orders.paid_email_claimed_at` (migration `0008`, additive `IF NOT EXISTS`, applied to the `hvile-verify-db` `storefront_v2` database) is the in-flight claim lease of the ONE paid-email send — `claim: true` stamps it (only for `paid`/`fulfilled` orders whose `paid_email_sent_at IS NULL` and whose lease is free / 2 minutes expired) and answers `claimed: true, paid_email_sent: false`, because `paid_email_sent_at` is stamped ONLY when the actual dispatch succeeds. `EmailDeliveryRequest` gained `kind` (`"reservation"` | `"paid"`): `sent: true, kind: "reservation"` clears `email_last_error` ONLY (never stamps the PAID-email ledger or touches the paid claim); `sent: true` otherwise stamps `paid_email_sent_at` (COALESCE'd, settled orders only), releases the claim and clears the error; `sent: false` releases `paid_email_claimed_at` and records `email_last_error` WITHOUT ever wiping an already-confirmed `paid_email_sent_at` (a failed manual re-send can no longer un-tell a customer who was already told).
- **Claim + try/catch claim release on ALL automatic paid-email paths (`G02`)**: `web/app/api/webhooks/stripe`, `web/app/api/orders/[code]/pay-card` and admin `confirm_fps` all claim via `claimPaidOrderEmail` BEFORE dispatching and, on ANY post-claim failure (receipt build, transport, ledger), release the claim through the delivery ledger in a `catch` so the send is retried/re-sendable instead of staying "in flight"; admin `resend_receipt` reports `kind: order.status === "reserved" ? "reservation" : "paid"` so re-sent hold confirmations never mark the PAID email sent.
- **Fail-closed admin logout (`G17`)**: `POST /api/admin/logout` now resolves the DB pool with `state::require_pool` — a deployment without `DATABASE_URL` answers `503` instead of pretending the session was revoked while the token still turns.
- **Deploy hook robustness (`OPS-01`)**: `scripts/vps.mjs` waits for `pg_isready` after `docker compose up -d db` before applying `0008`, no longer suppresses a failed uploads `cp -a` into the `uploads_data` volume (a copy failure FAILS the deploy), re-owns preserved uploads to `1000:1000` so the web container can still write NEW uploads, and runs `docker compose restart caddy` after `up -d --build` so the bind-mounted `ops/Caddyfile` is actually reloaded.
- **Last-unit lost-response recovery (`G01`)**: new `hasPendingAttemptForSlug(slug)` in `web/lib/recent-order.ts` finds a non-expired `lamp_pending_attempt_v2` entry in the product's `${slug}:` fingerprint namespace (the fingerprint is now `${leadSlug}:${lines}|${method}|${email}` — same identity semantics); the Product Story page sets `canRecoverPending = isSoldOut && hasPendingAttempt` and allows opening/submitting the express checkout when `!isSoldOut || canRecoverPending`, so a lost response on the LAST unit can be replayed (same `idempotency_key` -> the original order) instead of being blocked by its own ghost hold.
- **LANG-01 completed (no English product-copy fallback)**: removed every `?? <product>.content.en` fallback from `web/components/product-story-client.tsx` (incl. sibling swatches), `web/components/checkout-settlement-client.tsx` and `web/app/[lang]/products/[slug]/page.tsx` / `web/app/[lang]/checkout/[code]/page.tsx`; `zh-HK` routes now render locale-strict copy, a localized not-found metadata title (`找不到作品 | <brand>`) and a localized default `enquiryMessage`.
- **Tests**: Rust — reworked the claim/release lifecycle pin to the claim-vs-delivery split (won claim `paid_email_sent: false`, loser stays silent, release/re-claim, delivery stamp + claim release) and added lease-expiry recovery, `kind: "reservation"` non-stamping / non-stealing of the in-flight claim, and failed-re-send durability of `paid_email_sent_at` (264 tests green); web — `${slug}:` fingerprint namespace pin, `hasPendingAttemptForSlug` recovery matrix (present / other slug / prefix boundary / expired / no storage) and `kind` passthrough in `recordOrderEmailDelivery` (24 tests green).

### Reviewer (`gpt-6.1-sol`) findings fixes — Bounded Task 3
- **Webhook-only settlements send the paid email (`ops/Caddyfile`)**: `/api/webhooks/stripe` now routes to `web:3002` (the Next.js webhook route) instead of `api:8080`, so a webhook-only settlement both settles in the API AND sends the paid receipt + revalidates the cache (`/health` still probes the API directly).
- **Atomic paid-email claim & unpaid resend guard (`G02`)**: `POST /api/orders/{order_code}/email-delivery` gained `claim: true` — an atomic `status IN ('paid','fulfilled') AND paid_email_sent_at IS NULL` claim where exactly ONE caller gets `claimed: true`; `sent: false` (a failed dispatch) RELEASES the claim (`paid_email_sent_at = NULL`) and records `email_last_error` so a retry/admin re-send can succeed; `sent: true` only stamps `paid_email_sent_at` on `paid`/`fulfilled` orders (a re-sent reservation email on a `reserved` order never marks the PAID email sent). Web layer: new `claimPaidOrderEmail()` used by `webhooks/stripe` and `pay-card` before dispatching (fail-closed), with `recordOrderEmailDelivery` reporting the failure outcome. `OrderResponse` gained `idempotent_replay` (true on replay) and `/api/orders/reserve` only dispatches the hold email for fresh orders (receipt built in the ORDER's stored locale).
- **Reservation idempotency closes the last-unit race (`G01`)**: `reserve_once` re-checks `load_order_response_by_idempotency_key` before returning `insufficient stock` when a keyed attempt loses the race for the last unit in stock. Client side: `lamp_pending_attempt_v2` in `localStorage` durably stores the pay-attempt identity keyed by fingerprint (items + payment method + lowercased email, 30-minute TTL) — `getOrCreatePendingAttemptKey` / `clearPendingAttemptKey` in `web/lib/recent-order.ts` — so a refresh, lost-response retry or second tab with the same cart + email reuses the SAME `idempotency_key` and recovers the order.
- **Admin session uniqueness & fail-closed logout (`G17`)**: session tokens carry a `jti` (timestamp-micros hex + monotonic counter) so two logins in the same second can never mint the same token/revocation hash (pre-`jti` tokens stay valid to `exp`); `require_admin` no longer tolerates a missing `revoked_admin_sessions` table (`42P01` fail-open arm removed — revocation checks fail closed on ANY DB error); `/admin/api/logout` keeps the cookie and redirects `303 /admin?error=Logout+failed—please+retry` when server-side revocation fails with `status >= 500`, never falsely claiming success.
- **Production upload serving, streaming size limit & strict magic bytes (`G18`)**: PNG detection requires the FULL 8-byte signature (`89 50 4E 47 0D 0A 1A 0A`), AVIF requires `ftypavif`/`ftypavis` at offset 4 (`mif1`/`miaf`/`heic` boxes refused); `/admin/api/upload` streams the body under a hard 16 MB byte counter (chunked bodies can no longer bypass `content-length`) and returns `/api/uploads/{uuid}.{ext}` URLs served by the new read-only `GET /api/uploads/[filename]` route (strict filename regex, extension-derived `Content-Type`, `X-Content-Type-Options: nosniff`, `Cache-Control: public, max-age=31536000, immutable`) so runtime uploads are served immediately under `next start`.
- **Settings validation, studio draft guard & deploy ordering**: `contact.whatsapp` must contain 7–15 actual digits (spaces/dashes stripped) and `site.url` must parse via `new URL` with `http:`/`https:` and a non-empty hostname; the Product Studio marks dirty on the Clear-photo buttons and tracks an edit counter (`editVersionRef`) so `clearStudioDraft` on save completion only clears the draft when NO newer edits arrived while the save was in flight; `Re-send Receipt` is only offered/accepted for `reserved`/`paid`/`fulfilled` orders; the `scripts/vps.mjs` deploy hook now runs `docker compose up -d db` -> applies `0008_payment_email_session_hardening.sql` -> migrates any existing container `/app/public/uploads/.` into the `uploads_data` volume -> `docker compose up -d --build`.
- **Tests**: new Rust coverage (same-key concurrent last-unit reservation race, full claim/release/re-stamp lifecycle, `jti` uniqueness + legacy-token verification, `claim` request defaults) and new web coverage (`claimPaidOrderEmail` contract, strict PNG/AVIF magic-byte matrices, WhatsApp digit boundaries, URL parsing, durable pay-attempt keys incl. TTL expiry) — 263 Rust tests + 22 web tests green.

### Payment / Email / Session Robustness (backend hardening, findings `2026-10-21`)
- **Reservation idempotency — one order per pay tap (`G01`)**: Added migration `0008_payment_email_session_hardening.sql` (`orders.idempotency_key TEXT UNIQUE`) and an optional `idempotency_key` on `POST /api/orders/reserve` (body field or `Idempotency-Key` HTTP header fallback, <= 128 chars). A retried pay attempt returns the FIRST order without reserving stock twice, including under concurrent retries (the UNIQUE constraint picks one winner and the loser returns the winner's order).
- **Order-stored locale (`G02`)**: `orders.locale` (`'en'` | `'zh-HK'`, LANG-01, default `'en'`) is validated on reservation, persisted, and echoed on `OrderResponse` / `PublicOrderStatus` / `AdminOrder` / `WebhookResponse` so every paid/FPS email can speak the customer's language.
- **Paid-email delivery ledger (`G02`)**: Added `orders.paid_email_sent_at` / `orders.email_last_error` and `POST /api/orders/{order_code}/email-delivery` (`{"sent": bool, "error": Option<String>}` -> `{"ok": true, "paid_email_sent": ...}`) so the web tier (webhook, verify-session return, direct card, admin confirm-fps, admin resend) atomically records delivery/failures and dedupes sends; `POST /api/webhooks/stripe` now returns `order_code`, `customer_name`, `customer_email`, `locale` and `paid_email_sent` so the webhook-only settlement path can address the paid-confirmation email.
- **Server-side admin session revocation (`G17`)**: Added `revoked_admin_sessions` (token SHA-256 deny-list, never the token) and `POST /api/admin/logout` (behind `require_admin` + CSRF) which revokes the session server-side and clears the cookie; `require_admin` refuses any listed, unexpired token hash from that moment on.
- **Tests**: Unit coverage for the new validation rules, `token_sha256_hex` known answers, and cookie-clear contract; DB-backed coverage for reservation idempotency (body + header + normalisation + race-safe uniqueness), locale persistence + webhook metadata + email-delivery ledger round-trips, and logout revocation witnessed in Postgres.

### Payment / Email / Session / Upload Robustness (web + ops hardening, findings `2026-10-21`)
- **Paid-email recipient handling, localization & recovery (`G02`)**: Webhook-only settlements (`web/app/api/webhooks/stripe`) now load the order + storefront and send the localized paid receipt (`isLocale(order locale) : "en"`) to `customer_email`, recording every outcome via `recordOrderEmailDelivery` -> `POST /api/orders/{code}/email-delivery`. `sendPaidConfirmationIfSettled` accepts `alreadySent` (`paid_email_sent` — durable dedupe), `recipientEmail` (`webhookData.customer_email || session email || body.customerEmail`, fixing the direct test-card silent skip) and the stored `locale`; admin `confirm_fps` builds receipts in the order's locale (no more hardcoded English) and a new `resend_receipt` admin action rebuilds + re-dispatches the receipt (redirecting `?saved=` / `?error=`). - **Stripe return verification cross-check (`STRIPE-01`)**: `verify_session` now rejects sessions whose `amount_total` / `currency` disagree with the DB-authoritative order (`400 "Stripe session amount or currency mismatch"`) before forwarding the settlement event.
- **Reservation idempotency wiring & recovery (`G01`)**: `/api/orders/reserve` forwards `locale` + `idempotency_key` (body or `Idempotency-Key` header); Shopping Cart drawer and Product Story checkout mint one key per pay attempt (a `useRef` that only rotates when cart/selection/email changes or a reservation succeeds) and remember `{order_code, created_at}` in `localStorage` (`lamp_recent_order_v2`) so `/[lang]/orders` offers a one-click **Resume recent order** chip.
- **Transport fallback (`G15`)**: `dispatchTransactionalEmail` no longer gives up when Resend fails — it logs a warning and falls through to the configured SMTP transport, reporting a combined failure detail.
- **Admin session & CSRF hardening (`G17`, `G23`)**: `/admin/api/logout` revokes the token server-side (`POST /api/admin/logout`) before clearing the cookie; every `/admin/api` mutation route checks `verifySameOriginRequest` (Origin/Referer vs `x-forwarded-host`/`host`, `403` on cross-origin); the Product Studio mirrors all edits into a `sessionStorage` draft (`lamp_studio_draft_${id}`) restored after an interrupted session so session expiry never loses operator work.
- **Upload hygiene (`G18`)**: `/admin/api/upload` rejects `content-length > 16 MB` before buffering, enforces a JPEG/PNG/WebP/AVIF MIME allowlist AND magic-byte proof (`FF D8 FF`, `89 50 4E 47`, `RIFF....WEBP`, `ftypavif`/`ftypavis`/`mif1`) with declaration/content agreement, and stores files as `crypto.randomUUID()` + canonical extension. Operator uploads persist on the new `uploads_data` named volume (`docker-compose.yml`), and the `scripts/vps.mjs` `post-receive` hook applies `0008_payment_email_session_hardening.sql` idempotently to the running `db` container on every deploy.
- **Frontend resilience & polish (`G23`)**: `loadStorefrontData()` degrades to `{}` when `/api/site-content` or `/api/settings` fail (catalogue still required), GA4 renders only with a validated `analytics.ga_measurement_id`, `prefers-reduced-motion` shortens all transitions/animations, self-service hold cancellation requires a two-step inline confirmation, and admin Settings saves validate `analytics.ga_measurement_id` / `contact.whatsapp` / `site.url` formats (redirecting `?error=...` on invalid input).
- **Tests (`web/test/storefront-and-admin.test.mjs`)**: 18 passing unit tests including upload magic-byte accept/reject matrices, settings format validation, receipt generation (en/zh, multi-SKU), `recordOrderEmailDelivery` ledger payload contract, and the Resend->SMTP fallback path (no live external calls).
