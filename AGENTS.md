## Storefront & Operator Studio Frontend Rules
- Follow the global **Frontend & CSS architecture guardrails (intrinsic layout, zero magic numbers)** in `~/.pi/agent/AGENTS.md`:
  1. **Language tag (`LANG-01`):** The language switcher displays `EN` and `中文` (never `繁體中文`). Every route renders strictly one locale.
  2. **Zero `EN` ↔ `中文` layout shift (no magic widths):** Use the 3-zone header grid (`grid-cols-[1fr_auto_1fr]`) and intrinsic `[grid-area:1/1]` hidden-label stacking for bilingual controls so switching between `/en` and `/zh-HK` produces zero horizontal jump without hardcoded `w-[...]` or `min-w-[...]` pixel/rem widths.
  3. **100% first-fold Hero visibility on 16:9 and 16:10 laptops (no magic heights):** The first fold (sticky header + telemetry bar + Hero section) uses viewport-bounded flex/grid sizing (`lg:min-h-[calc(100dvh-var(--header-height))]` / `lg:max-h-[calc(100dvh-var(--header-height))]` / `flex-1 min-h-0` on the carousel stage) so the entire Hero left column and right-hand rotating carousel card (including title, price, and CTAs) are 100% visible without scrolling on both 16:9 (`1440×740` inner window) and 16:10 viewports. The custom property is spelled `--header-height` everywhere (`globals.css`, `exhibition-header.tsx`, `exhibition-home-client.tsx`, `product-story-client.tsx`) — no `--header-h` alias.
  4. **Product Lineup Cards (`subgrid`):** Both Gallery I (Flagship PH Table Series) and Gallery II (Panthella 160 V3 Portable Series) align card rows across columns using CSS `subgrid` (`grid-rows-subgrid`), never magic `min-h-[...]` heights.
  5. **Zero competitor price comparisons:** Never display showroom reference prices (`HK Showroom`, `Save %`, `15% under retail`, `陳列室`) on storefront cards, hero copy, or PDPs.
- **Mobile-first cross-device guardrails (lamp storefront):** Also obey the global **Mobile-First & Cross-Device Responsive Architecture (320px -> 1440px+)** block in `~/.pi/agent/AGENTS.md`; the following are the lamp-specific consequences.
  6. **2-tier mobile exhibition header (`< md:`, i.e. `< 768px`; the 3-zone grid applies from `md:` `>= 768px` up):** Primary navigation is never removed on mobile. Below `md:` the header stacks two rows. Row 1 = Brand identity (protected, non-shrinking slot: `brand.logo_url` when configured, else the `brand.name` / `brand.name_native` wordmark) + Utilities (locale switcher `EN`/`中文`, Daylight 5500K ↔ Nocturne 2700K atmosphere toggle, cart button with count). Row 2 = `Collection | Provenance | Order Lookup` (`ui.navCollection`, `ui.navProvenance`, `ui.navOrderLookup`) as one calm strip that may scroll inside its own track (`overscroll-behavior: contain`) but never widens the page. From `md:` (including the `768x1024` tablet) the same markup collapses into the single-row 3-zone grid (`md:grid md:grid-cols-[1fr_auto_1fr]`: brand · centre nav · utilities) — 768px is *not* a mobile-header viewport. Both rows live in the single sticky `<header>` whose measured height feeds `--header-height`, keeping `scroll-padding-block-start`, the `lg:` Hero fold and the PDP sticky column correct at every width. That measurement comes from a `ResizeObserver` on the header's **inner content wrapper** (its `getBoundingClientRect().height` plus the `<header>`'s own border chrome, coalesced to one measurement per animation frame, re-run on resize/orientation and after `document.fonts.ready`) — never from the outer `<header>`, which consumes `min-block-size: var(--header-height)` and would therefore ratchet its own input taller on every pass (monotonic resize feedback loop). Below `lg:` the hero scrolls naturally with the document: the first-fold fit is a laptop-only rule, never a mobile excuse to clip content.
  7. **Presentational-UI-only localized brand fallback:** `brand.name` resolves to an empty string when unconfigured (`NAME-01`/`ENV-01` resolution: settings override -> env default -> code default) — `resolveSiteConfig().brandName` stays exactly `""` in that case and is never rewritten: no placeholder is persisted back to `settings`/DB state, and `brandName` is never back-filled before the FPS payee resolution (`fpsAccountName ?? brandName` stays honest — the payee name comes from `payment.fps_account_name`, never from display copy). Localization happens **purely at render time**: UI surfaces and metadata substitute the localized `ui.defaultExhibitionTitle` (`LIGHTING EXHIBITION` / `建築燈飾典藏展`) only when `config.brandName.trim() === ""`, so the storefront still renders a localized, presentational-only placeholder in the brand slot (and in `<title>`/footer metadata) — never a hardcoded real brand name, never a blank or zero-width node — and the protected brand region keeps readable intrinsic width at 320px. The fallback is display-only: it is never used to name a variable, database or container, and it disappears automatically once `brand.name` or `brand.logo_url` is configured.
  8. **`@container` storefront cards and panels:** Hero carousel card, Gallery I/II lineup cards, the PDP purchase panel, and cart/checkout line items declare `container-type: inline-size` and size their internal price/spec/CTA grids from the container's own inline width (1-up phone -> 2-up tablet -> 3-up `lg:`), while `subgrid` cross-card row alignment still applies inside the `lg:` grid. **`container-type` and `subgrid` cannot coexist on one element:** inline-size containment disqualifies that element from participating in a parent `grid-template-rows: subgrid`, so the lineup `<article>`s keep `row-span-N grid grid-rows-subgrid` **without** `@container`, and the `@container` lives on the inner CTA/footer wrapper (the price + CTA block) — or on a wrapper around the parent grid — so `subgrid` cross-card row alignment and `@container` stacked↔inline CTA switching work simultaneously. Any PR that moves `@container` onto the card root is a regression of one or the other.
  9. **Hero carousel pause/play + `.reel-*` indicator strip:** The auto-rotating Hero carousel exposes a visible, keyboard-reachable pause/play toggle (`aria-pressed` reflecting the manual pause state) and a numbered `.reel-*` indicator strip (`.reel-1` ... `.reel-N`; the current reel marked with `aria-current="true"` plus `data-active="true"` as the styling hook). **Manual pause persists for as long as the component is mounted** — it survives slide changes and transient hover/focus pauses (`carouselPaused`), so a visitor who stops the rotation is never overridden by the timer, the next tick, or a mouse-out; autoplay never starts under `prefers-reduced-motion: reduce`, each indicator names its piece for assistive tech, and every control stays touch-safe: `>= 36x36px` for the `.reel-*` indicator buttons and the pause toggle, `>= 44x44px` on the primary Hero CTAs, without introducing horizontal overflow at 320px.
